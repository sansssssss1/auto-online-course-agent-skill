# 学习通共用知识

网课与作业共用本文件；授权、提交范围和交付物由各自流程决定。工具调用见 `../adapters/`，平台页面实际表现优先于历史选择器。

证据标记：**本机**为旧版运行记录；**朋友**为上游实战案例；**待验证**为新版尚未完成的验证。旧版网课仅在 ZCode 实战过，旧版作业在 ZCode、Codex 均实战过；这不证明新版全流程已通过。

## 1. 会话与课程入口

- 从 `i.chaoxing.com` 个人空间的课程卡片进入，观察打开的目标标签；`opencoursenewfy` 链接及 `enc/openc/ckenc` 等参数可能轮换，复用旧快照拼直链曾失败。
- 目录常在 `mooc2-ans.chaoxing.com/mooc2-ans/mycourse/stu`，学习页常在 `mooc1.chaoxing.com/mycourse/studentstudy`；域名或标题只作定位线索，登录状态还需看当前页面骨架、重定向和课程内容。
- 学习页顶层可能没有用户名，不能据此判定掉线。遇到登录页，用本次已授权的登录方式恢复；已有有效授权时无需逐次重问。
- 账号密码、Cookie、完整会话 URL 只留本地私有数据目录。填过密码后避免输出整页快照：本机作业记录出现过密码框 value 被快照明文输出，改为读取不含凭据的登录结果。
- 登录控件曾为 `#phone`、`#pwd`、`#loginBtn`；本机某版 ZCode 中按钮点击无效而页面原生登录函数有效。仅在当前适配器支持且已观察到该函数时使用，不把此函数当作跨版本接口。

## 2. 列表巡检与详情取题

- 巡检停在课程、章节、作业或测验列表，采集标题、状态、截止时间、稳定任务标识和可见提示，再比较上次快照。
- 作业列表常在 `#frame_content-zy`。本机见过 `li[onclick*='goTask']` 的 `data` 属性包含平台生成的详情链接；可读取链接用于定位，但巡检不导航过去。
- **本机作业经验**：`work/task` 打开后可能跳到 `dowork` 并生成 `answerId`。打开详情可能开始作答记录；计时或限次任务须先读入口说明并按已授权范围操作。
- 截止时间采用当前平台显示；缺失年份或时区时保留原文，不能静默猜成另一天。状态未知写为未知，空列表先核对加载及登录状态，不能判定全部完成。
- 需要取题时才打开当前列表生成的详情链接。不要把其他课程、上次会话或过期参数拼成链接。
- `scripts/collect_task_list.js` 是受支持页面脚本通道里的只读当前列表采集函数，不导航、点击或提交。调用方以显式参数提供 platform 与 scope（account_alias、course_key、view），保存其返回的列表快照。生成与执行方式见 `tool-data.md`。
- `scripts/inspect_tasks.py` 只汇总和比较本地快照；`summary --input snapshot.json`，或 `diff --before a.json --after b.json --out changes.json`。不同 scope 拒绝比较；采集端须保留任务 ID，仅靠标题会混淆同名作业。

## 3. 页面结构与选择器线索

旧版实战观察到的结构如下，各层是否同源、工具是否支持跨帧要在现场确认：

```text
课程目录 → #frame_content-zj / studentcourse iframe → 章节行
学习页 → #iframe（knowledge/cards）
          ├─ iframe.ans-insertvideo-online → video
          └─ iframe[src*='ananas/modules/work']
               └─ #frame_content（api/work）→ .TiMu / .questionLi
作业列表 → #frame_content-zy → goTask 行 → dowork 详情
```

- 两代目录都出现过 `.chapter_item#cur…`、`.posCatalog_select`、`.posCatalog_name`；按当前节点文本与身份定位，不固定认定哪代一定存在。
- 卡片页 `mArg.attachments` 曾包含 video/document/workid/read/live 及 `isPassed`。它是辅助任务身份和完成核验的页面数据，不是写入进度的入口。
- 有「学习目标 / 视频 / 章节测验」多部件时，先打开当前节对应部件。`attachments` 为空可能只是尚未按需加载。
- 全帧搜索可能找到上一节残留播放器；起播前核对本节附件 `objectId`、实际媒体源与节次，时长接近不足以判同一视频。
- “下一节”可能整页跳转，也可能只换部件。重新核对当前章节、附件、题面及脚本实例，不能沿用旧对象推定已切节。

## 4. 播放、续跑与完成核验

- 真实操作平台播放器，让平台自行记录；不调用文档/视频完成接口代替学习，不伪造进度、心跳或行为监测请求。
- `preload=none` 可能要点击播放才开始加载。先用平台播放控件；程序调用只能在适配器明确支持且确认当前视频身份时作为恢复方式。
- 倍速仅选择当前官方菜单允许的值。控件隐藏、拖动限制或速率固定时接受平台限制，锁速课程不用旧版会强设 2x 的 keepalive。
- 健康判据以两次观察间 `currentTime` 是否推进为主；`readyState=4`、`error=null`、`visibilityState=visible` 都不足以证明正在播放。
- 暂停时先查弹题、错误、加载、登录、标签状态和视频身份，再做一次恢复并回读。避免多个 watcher 同时控制同一视频。
- `ended` 仅表示媒体结束。完成后重新核对本节对应附件 `isPassed`、平台完成标记和目录状态；旧快照或单个树计数不足以验收。
- 计数可能混合视频、文档和测验；不能用“待完成≤1”普遍推断视频已完成，也不能固定认为总任务点=视频数×2。
- 补播只针对确认漏分的任务，按当前稳定身份重定位。本机存在从服务器约 420 秒续播的记录；朋友也有从零重播的例子，不能统一要求锁速课一次连续看满。
- 空章节、文档和阅读均按页面正常打开与提示处理，完成仍回到平台核验。HTTP 200 或工具调用成功本身不代表任务完成。

## 5. 静音优先与低音量短试

默认静音。**本机**有 `muted=true` 真正静音并完成 60/60 的记录；**朋友**后台 watcher 曾报告 `video-only background media was paused to save power`。本机未独立复现该报错；另一次 `muted=false, volume=0.001` 成功记录没有做对照，不能证明取消静音必要。

静音下仍反复暂停或时间不推进，在排除 §4 的常见原因后，可对**当前同一视频**短试 `volume=0.001`，最长 60 秒：

1. 核对当前视频及非空 source，记录原音量，确认没有其他脚本持续改声音。
2. 先静音、设音量，再暂时取消该视频静音；不提高系统或应用音量。
3. 观察时间推进和暂停频率；无改善、声音干扰、报错或切节时立即结束。
4. 在 `finally` 中重新定位当前视频，把试用旧视频与当前视频都静音，再恢复旧视频原音量并清除试用状态。

即使有效也先恢复静音、记录环境，不自动续期或推广到整课。后台计时器可能延迟，不能仅依赖脚本超时收尾。`0.001` 不保证每台设备完全不可闻；无受支持的脚本执行通道时，只通过平台已有音量控件操作，不为短试接入隐藏调试接口。

## 6. 当前题面与混淆字体

- 每次取题先记录课程、任务、节次、题号、首题片段和采集时间，图像与文字须对应当前页面。新测验重新取字体，不复用上一套缓存。
- 已核对的明文优先；`aria-label` 只在与可见内容一致时辅助。`font-cxsecret` 下 DOM 看似汉字也可能是错误编码。
- **本机**曾见跨页映射 0/218 命中；全局字符映射不成立。同页已核对映射可辅助复读，不能跨页直接套用。
- 截图可用时保留题干、题号、显示选项标签、公式和图形对应关系。题图过期时丢弃该采集结果，不凭旧图作答。
- 支持页面脚本时，可在题目所在文档等待字体加载，按文本节点实际 computed font 逐字渲染；混合字体不能整段套一个字体。
- **本机 10/10**曾遇到 canvas/toDataURL 与截图返回旧内容，改取当前题页内嵌 TTF，混淆字使用该套字体、其余使用普通字体，逐字混排成行，再用 RapidOCR 行级识别。
- 行级 OCR 在那次实战比单字/整图稳定，仍需核对否定词、数量、公式、题号和选项；缺字或低置信度保留为待复核。
- 新版 `scripts/collect_questions.js` 是在已打开题目帧运行的只读采集函数，不是 Node CLI；仅通过受支持页面脚本通道调用，返回离线 reader 所用 JSON。格式与显式参数见 `tool-data.md`，`scripts/question_reader.py` 负责离线渲染/OCR，参数看其 `--help`。采集成功不等于题意已确认，当前验证范围见 `validation.md`。
- 无受支持的页面脚本能力时，使用当前工具提供的 DOM 快照、截图或用户已保存的本地题目/字体；不能声称已执行 TTF 回退。

## 7. 选项与弹题

- 含图片的选项先按 §9 硬性步骤用 `merge_images.py` 拼合，只读拼合图，不逐个 Read 原图。
- 章节题的显示字母与内部编码可能不同。**朋友**有显示 B 而内部值 C 的案例；本机后续按 `.num_option_dx.textContent` 找显示标签。
- 按题号、可见选项文字和显示标签定位，不把 `data`、hidden 值或 aria 编码固定当作显示字母。点后核对真实 radio/checkbox、选中样式和表单变化。
- 读回表单可能遇到异步暂态，应再次读取。多选按目标集合核对，重做时清掉不需要的旧选择。
- 弹题常在 `.tkTopic`，选项 `input[name='ans-videoquiz-opt']`；按钮曾为 `#videoquiz-submit`、`#videoquiz-continue`。按当前可见层定位。
- **本机**点 `li` 曾没有选中 radio，需点击实际输入控件并核对 checked，再提交。答错浮层可能滞留且视频继续，不把继续播放当作答对。
- 发现未答或答错滞留层及时处理；弹题寿命、是否影响计分因课程而异。朋友有晚答漏分案例，本机也有先完成任务点再补答的反例。
- 多个答题模块共存时确认实际由谁取得当前题面并作答；朋友曾因新旧模块互相让位而无人答。新版默认仅一个执行者。

## 8. 提交事务与重做

本节描述平台机制，不授予作业或测验提交权限；先遵循 `homework-flow.md` 或 `course-flow.md` 的当前授权。

1. 读本次时限、可用次数和附件打开限制；完整读题并核对已选答案。朋友某课有限次，不能推广成每节只有一次。
2. 提交前处理“当前章节还有任务点未完成”等提示；不要关闭未读确认层。
3. 章节测验曾用 `a.btnSubmit` → 顶层可见 `.popDiv.Marking` 的“确认提交” → 该层提交按钮。具体文案和层级以当前页为准。
4. 两步之间不要调用 `closeDeleteWindow()`，朋友与本机记录均提示它可能把提交确认一起关掉。
5. 成功核对结果页、提交记录和按钮变化；再独立核对平台任务点。工具超时先查状态，不能盲目重提交。

分数、公开正解、重做入口和剩余次数按当前课程读取。部分低分不计任务点，部分低分也计；部分能重做，部分没有。重做须在当前授权与平台允许次数内进行。旧记录的个人长期授权不自动转为所有使用者的默认授权。

## 9. 附件与图形

- **本机作业**：附件 iframe 的 `name` 曾含 base64 对象信息，可从已观察到的结构解出 objectId；不要假设每个附件同款。
- 受支持页面通道可读平台返回的附件元数据，取其中真实 `pdf` / `download` 地址。某字段下载成 403 HTML 时核对内容类型、文件签名与大小，再尝试平台给出的另一字段，不把错误页存成 PDF 交付。
- 题干图片有防盗链时优先使用已登录页面显示、截图或平台正常下载。某次新标签打开原图可读并不保证当前环境也可用；跨源 fetch 失败时换受支持通道。
- 图形选项保留标签及原图一一对应。**硬性步骤：读取选项图前必须先用 `scripts/build_merge_manifest.py`
  归集分组，再用 `scripts/merge_images.py` 本地拼合（按题号分组、纵向白底、默认高分辨率
  `min_width=600`，LANCZOS 等比放大），模型只读拼合图，禁止逐个 Read 原始选项图，原图保留不删；**
  不能裁掉条件或互换选项顺序，缺图/坏图按脚本非零退出先修复，不跳过。
- **补读原图仅限复核场景**：拼合图仍无法确认（如 P 调色板小图、需核对单像素笔画或细小公式）
  时，必须先读拼合图确认不足，再按标签定位单张原图核对；不允许跳过拼合直接逐个 Read 原图。

## 10. 故障与证据边界

| 观察 | 处理与边界 |
|---|---|
| `jobCountDiv` 显示每日任务点上限 | 保存当前状态，停止当日受限视频任务；不切接口绕过。 |
| 验证码、登录挑战、滑块 | 保留任务断点，使用平台正常验证与当前工具支持的人机交互。 |
| 直接拼卡片链接或快速跳章后拦截 | 回正常课程入口；减慢导航，等当前页面加载，不反复探测参数。 |
| 无焦点、最小化、熄屏后停摆 | 恢复目标页面可观察状态，再比较时间推进；旧版后台保活个案不构成新版锁屏保证。 |
| 解码或网络错误 | 确认当前视频身份，先平台恢复控件；必要时刷新并按服务器保存进度恢复。 |
| 同一通道反复失败 | 记录失败与当前任务，换已支持回退通道；不要反复改选择器直到碰巧成功。 |

新版脚本的离线检查只证明输入输出和局部行为；平台真实计分、截图新鲜度、登录与长时间播放须单独实战验收。新证据记录环境、现象、操作、结果与反例，避免把一次成功固化为平台通则。
