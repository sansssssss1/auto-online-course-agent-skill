# 作业交付与验收

此文定义交付格式。课程专用路径、模板、收件夹和历史先例见 `local/homework-profile.md`；探测当前解释器、命令与字体，不把历史安装状态当作当前保证。

## 内容结构

- PDF 首页为答案速查表，每题一行：题号与最终结果；主观题可写结论概要。
- 正文每题保留可核对的题干/来源，接蓝色边框或浅蓝底的【规范作答】与独立的【详解】。规范作答写完整步骤，详解说明选择方法、易错点和必要的背景。
- 使用中文、有辨识度的文件名，例如 `{课程}第{N}次作业_{章节范围}_参考解答.pdf`。不需要封面堆积空页。
- 程序题交付可运行源码、运行方法、实际输出与需要的真实截图；网页需上传图片时另做按顺序编号的图片包、粘贴文本和提交步骤。截图不能由绘图或排版伪装成软件运行。

## 排版选择

| 内容与条件 | 选择 |
|---|---|
| 重公式、矩阵、分布和中文；Typst 可用 | 优先 Typst |
| 文字证明、简单公式 | Typst 或 ReportLab |
| 已有 KaTeX 模板或 Typst 不可用 | 本地 KaTeX 静态 HTML + 浏览器打印 |
| 已有可编辑 Word 文件需要转换 | 可用时用 LibreOffice；复杂公式转换后检查 |

Codex 遇到 PDF/文档任务时先读取当前可用的 PDF/文档技能及运行时说明，使用实际提供的库与预览方式。ZCode 使用其适配文档探测现有命令。排版选择服务于这次内容，不为统一而重写已合格旧产物。

### Typst 起始模板

```typst
#set page(margin: 2cm)
#set text(font: ("Libertinus Serif", "SimSun"), size: 11pt, lang: "zh")
#show math.equation: set text(font: ("New Computer Modern Math", "SimSun"))
```

先核对这些字体当前可用；需要时换成当前环境支持的中文、正文及数学字体。编译采用 `typst compile <source.typ> <output.pdf>`，读取真实诊断。

经旧版实战观察的注意点：

- Typst 不是 LaTeX，按当前 Typst 语法写公式；数学多字母标识要确认是符号名还是变量相乘，变量相乘用空格分开。
- 粗体使用 Typst 的 `*文字*`；检查空粗体、括号配平和编译 warning 的真实影响，再修复。
- 题干避免单行落在页底；长规范作答框允许跨页，保持题号与解答相邻。
- 如复用旧 linter，先核对它是否适配当前源文件；linter 通过不等于数学内容正确。

### 备用管线要点

- ReportLab 注册实际字体；先用集合、上下标、希腊字母与中文样本检查缺字。普通中文字体并不覆盖所有数学符号。
- KaTeX 数学源使用字面 `<`、`>`，避免 HTML 实体误入公式；检查错误色块与裸源码。浏览器无头打印使用独立临时 profile，输出到明确绝对路径。
- LibreOffice 输出到新的明确目录；同名输出可能造成无头等待。保留源文件，转换后核对公式和页码。

## 验收顺序

1. 核对题号覆盖、速查表与正文结果一致；独立复核关键推导与程序实际输出。
2. 重开生成的 PDF，检查页数、文字层、乱码与关键内容；数学斜体提取伪影回查源文件并读渲染图判断。
3. 将最终 PDF 渲染成页面图，检查缺字、公式裁切、框内溢出、孤立标题、空白页及截图清晰度。程序化颜色/文字扫描可辅助，不替代需要的页面查看。
4. 需要视觉子代理时先用一页轻量探针验证当前可用性；失败一次改为主会话读图与程序检查，不反复等待同一不可用通道，也不将本次结果写成永久能力事实。
5. 屏幕图返回旧画面时先核对页码、图文锚点及源文件；按适配说明切换可用图像通道，记录受限范围，不靠反复改文件名声称已验收。
6. 完成收件夹复制后运行文件交付闸门；有题目或视觉疑点时分别说明，文件闸门仍可检验已准备的部分材料。

## 文件交付闸门

接口保持旧版习惯：

```text
python <skill-root>/scripts/delivery_gate.py <manifest.json>
```

manifest 内相对路径以 **manifest 所在目录** 为基准，绝对路径也可用。至少一个产物；`contains`/`not_contains` 检查 PDF 文字层或 UTF-8 文本。图片等二进制文件只检查存在性、大小、新鲜度、可选哈希一致性；图片可读性另行看图。

```json
{
  "claims": ["本次参考解答及收件夹副本已准备"],
  "artifacts": [
    {"path": "解答.typ", "role": "source"},
    {"path": "参考解答.pdf", "role": "primary", "pages_min": 1,
     "contains": ["答案速查", "规范作答", "详解"], "newer_than": "解答.typ"},
    {"path": "收件夹/参考解答.pdf", "role": "copy",
     "sha256_equal_to": "参考解答.pdf"}
  ]
}
```

`0` 为通过，`1` 为检查失败，`2` 为用法/manifest 错误。主会话核对实际 manifest 后亲自运行，并在交付回复附原始 `GATE: PASS` 行。不要对不在清单中的图片包、覆盖范围或平台状态作完成声明。

来源：旧 `course-homework` 的 `references/pdf-pipeline.md` 与 `references/delivery_gate.py`；新版保留交付要求，消除了公共说明中的个人路径，并将闸门相对路径固定到清单位置。
