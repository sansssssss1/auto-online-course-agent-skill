# 网课流程

ZCode旧版网课有实战记录；Codex网课是本版需要独立验收的路径。两端不因文档相似就视为等价。
适配入口由 [SKILL.md](../SKILL.md) 路由，平台细节读 [学习通](chaoxing.md) 或 [中国大学MOOC](icourse163.md)。

## 列表巡检

读取当前课程目录、课件和测验列表，记录已发布范围、完成状态、可见截止时间。先核验登录态和课程身份。
使用 `collect_task_list.js` 时仅从已加载列表采集，不为巡检打开题页或开始测验；工具能力不足时手动整理同一数据格式。

`inspect_tasks.py summary` 统计的是当前快照，不自行证明整门课程已完成；空列表或结构变动应标未知。
与前次对比必须是相同账号别名、课程键和视图，不能把换号或换课程当作新任务发布。

## 断点与播放

1. 读本次状态和平台目录；定位进行中的计时测验，优先处理它，再安排课件。
2. 看平台标记确定待办。记录当前课程/节次/媒体身份；旧文件的 done 只作线索。
   分开盘点视频和测验，一节含多个视频时逐个核对；平台已确认完成的视频记“既有完成”，纯测验任务不为本轮证据重播。取材与回执见 [证据与效率](evidence-efficiency.md)。
3. 学习通先打开当前视频部件并核验源，静音正常播放；锁速接受1x，不使用会固定2x的旧保活脚本。
4. 中国大学MOOC保留已有的原生进度条策略：按平台支持的UI拖动、正常结束、回目录刷新后核验；
   无控件、操作失败或刷新不保存就回退正常播放。用户要求完整播放时从一开始按完整播放执行。
5. 文档让平台阅读器正常加载后回目录核验；有限等待后仍未知就保存原因，不把打开动作当作完成。
6. 每个节点结束和暂停时保存证据；每章汇报数量及异常，不为已经授权的后续步骤重复索取同一授权。

播放健康看 `currentTime` 的连续变化和平台状态，而不是只看 focus、ended 或没有异常日志。
发生失焦、暂停、无视频、解码错、掉登录或每日上限时，按平台知识处理；每日上限停止当日视频任务。
短期异常先保留现场，不能以反复刷新/开新标签作为默认恢复。

## 弹题与测验

弹题及时核对选中态与平台判定。章节测验先读实际限时、次数和已使用机会。
进入介绍页与“开始测验”要区分；后者可能启动计时，即使有效提交次数仍为0也不能随意离开。

已获本次作答和提交授权时：读全题 → 求解 → 逐题填写 → 回读保存状态 → 核对 → 提交及真实确认层。
题面、选项或图形不完整先补齐；OCR结果不自动成为答案。学习通显示字母与内部值可能不同。
MOOC选项可能自动保存，按平台实战建议节奏操作；遇节流退避后只补未保存项，不连点整卷。

成功以平台提交记录、尝试次数或明确结果页为证据。隐藏分数只报告已提交；不凭空猜分。
本次尝试提交一次；结果不明先查记录。重做是新的事务，必须在已有授权和剩余次数范围内，不能为查分盲目重做。

## 可选旧Runner

新版采用上述监督流程。旧Runner继续保留在本机原目录，位置记入 `local/legacy-paths.json`，
切换条件见 [回退说明](rollback.md)。它不由新版自动开始，也不把旧Runner称为新的seek-first执行器。
`scripts/official_seek.mjs` 只是已有Playwright会话的原生进度条辅助模块，不建立浏览器、登录或上报进度。

不将无头学习通Runner设为默认：旧实战有被切出会话的记录；若需要比较执行方式，另做有界验证。

## 收尾

课件与测验分开验收。重新读取/刷新目录后核对已发布课件，确认本次测验提交记录；
“所有已发布任务点完成”不等于结课或成绩达标。状态、题面、日志和输出本机保留，记录下一步。
